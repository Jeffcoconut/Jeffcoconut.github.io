# 百度搜索结果页的 HTML 结构示例

> 用于说明「父子嵌套的可交互元素」为什么需要去重（对应 `annotation_js.py` 的
> `dedupParentChild`）。

## 1. 简化版：父容器 + 子链接的双层结构

```html
<div class="c-container" style="cursor:pointer">   <!-- 父：卡片容器，带鼠标手势，判为可交互 -->
  <a href="...">东方财富网</a>                       <!-- 子：真链接，也可交互 -->
</div>
```

- **父 div**：一条搜索结果的整张卡片，挂了点击事件（`cursor:pointer` 是视觉信号），点卡片任何位置都跳转。
- **子 a**：只包住标题文字，是浏览器原生链接，点击必然触发导航。
- 两者都通过 `isInteractable` 判定——点得动，但点的是**同一个目标**。

## 2. 完整版：一条搜索结果卡片里装了什么

```html
<div class="c-container">                          <!-- 父：卡片容器 -->
  <h3>
    <a href="...">东方财富网</a>                     <!-- 子：真链接（标题） -->
  </h3>
  <p class="content_abstract">东方财富网,股票行情...</p>   <!-- 子：摘要文字 -->
  <span class="source">东方财富官方</span>                 <!-- 子：来源 -->
</div>
```

标题、摘要、来源、缩略图全装在一个容器里——这是现代搜索结果「卡片化」的典型结构。

## 3. 百度为什么写成这样

| 动机 | 说明 |
|---|---|
| 扩大点击热区 | 点摘要、点空白处都能跳转，不用瞄准标题几个字 |
| 卡片化布局 | 边框、悬停阴影、间距需要一个父容器做视觉单元 |
| 统一挂埋点/样式 | 父容器一个监听器统一处理跳转统计与悬停高亮 |
| 历史遗留与 SEO | 早期是纯 `<a>`，改版时外面套了 div，但真链接要保留（爬虫、右键新开标签、Tab 导航都依赖它） |

## 4. 不去重的四个连锁后果

1. **配额翻倍**：一条结果占两个座位却只代表一个目标；百度每条结果 2-3 层嵌套，一页 10 条就吃掉 20-30 个配额。
2. **截图蓝框叠蓝框**：父子各画一个框，大框套小框、编号紧挨着。
3. **LLM 困惑与执行风险**：列表里两条指向同一处，模型可能选父级——点 `<a>` 走原生导航必然跳转，点父 `div` 依赖 JS 监听器，点击落点（元素几何中心）若不在监听区域内就没反应，任务空转。
4. **拖垮分组算法**：父容器包围盒很大，与卡片内所有元素及相邻卡片"真相交"，是链式合并（整列并成一个巨框）的燃料。

## 5. 处理方式：`dedupParentChild` 删父留子

判定公式（满足其一即删父）：

- 几何判据：子框 ≥ 80% 面积被父框盖住
  `(interW × interH) / A_child ≥ 0.8`
- 语义判据：子是 `a`/`button` 且父是 `div`/`span`/`li`/`p`/`section`/`article`

被删的父元素连 `unique_id` 属性一起从 DOM 摘掉——保证「截图蓝框标号与元素列表一一对应」的承诺不被破坏。
