# 浏览器完整加载流程专业版详解（5 阶段模型）

> [!NOTE] 核心主线
> 该流程严格遵循用户输入的五步骨架，自底向上拆解浏览器内核（Blink/Gecko）的运作机制：`寻址与建连` -> `协议交互` -> `语法解析` -> `阻塞渲染` -> `生命周期就绪`。

---

### 1. DNS 解析与传输层安全握手（寻址与链路协商）

此阶段完成**域名到 IP 的映射**及**安全信道**的建立。

- **DNS 解析（递归与缓存）**：
  浏览器优先查询**本地多层缓存**（Hosts 文件 -> 浏览器 DNS 缓存 -> 操作系统缓存）。若未命中，则向本地 DNS 服务器发起**递归查询**，逐级（根域 -> 顶级域 -> 权威域）获取目标服务器的 **A/AAAA 记录（IP 地址）**。

- **TCP/TLS 握手（可靠性与加密）**：
  - **TCP 三次握手**：通过 SYN -> SYN-ACK -> ACK 建立面向连接的可靠字节流，确保数据包顺序与重传机制生效。
  - **TLS 协商（HTTPS）**：在 TCP 之上进行 TLS 握手（现代 TLS 1.3 支持 **0-RTT** 或 **1-RTT** 恢复），完成证书链校验与**对称会话密钥**的衍生，将明文升级为加密信道。

> [!TIP] 性能关注点
> **RTT（往返时延）** 是此阶段的绝对瓶颈。DNS 预解析（`dns-prefetch`）和 TLS 会话复用可大幅缩减此处耗时。

---

### 2. 发送 HTTP 请求与解析响应头（协议交互与元数据判别）

- **构建请求报文**：
  浏览器构建 **HTTP 请求行**（Method + URI + Version）及**请求头**（核心字段如 `Host`、`User-Agent`、`Accept-Encoding`、`Cache-Control` 等），通过 Socket 套接字发送至服务器。

- **解析响应头（元数据决策）**：
  服务器返回的首批数据为**响应头**。浏览器解析**状态码**（200 OK / 304 Not Modified / 301 Moved Permanently）以决定后续动作。
  关键头部字段包括：
  - `Content-Type`（决定 MIME 类型）；
  - `Cache-Control` / `ETag`（**强缓存**与**协商缓存**策略判别）；
  - `Set-Cookie`（服务端状态写入）。
  此时，浏览器尚未接收响应体，但已掌握资源的处理方式。从请求发出到收到第一个响应字节的耗时，定义为 **TTFB（Time To First Byte）**。

---

### 3. HTML 令牌化与 DOM 树的构建（字节流 -> 语法树）

此阶段为**增量式解析**，无需等待 HTML 全量下载。

- **字节流解码与词法分析**：
  浏览器将接收到的 **字节流**（Byte Stream）通过解码器转为字符，经由**词法分析器（Tokenizer）** 拆解为 **Token（标签令牌）**，如起始标签（`<div>`）、结束标签（`</div>`）及属性令牌。

- **树构建器（Tree Builder）**：
  令牌被送入**树构建器**，依据 HTML 规范（栈式开放元素与插入模式）构建出 **DOM 树（Document Object Model）**。此过程采用 **增量构建**，边下载边解析边生成节点。

- **关键加速机制 —— 预加载扫描仪（Preload Scanner）**：
  在主解析器构建 DOM 的同时，独立的**预加载扫描仪**线程会高速扫描剩余的字节流，提前发现 `<img>`、`<link>`、`<script>` 中的 URL，并**先行发起网络请求**，极大提高资源加载的并行度。

> [!IMPORTANT] 核心转折点
> DOM 树的构建在此阶段**仅完成了结构定义**，此时页面为无样式的裸结构，不产生任何像素绘制。

---

### 4. 资源加载、CSSOM 构建与 JavaScript 的阻塞执行（渲染管线的交织博弈）

这一步是主线程的**核心阻塞区**，涉及多资源的互斥加载。

- **CSSOM（CSS 对象模型）构建**：
  浏览器下载并解析 CSS 文件（含内联样式），将选择器（如 `.class`、`#id`）转换为树结构 **CSSOM**。**CSS 阻塞渲染**（即未完成 CSSOM 构建时，浏览器绝不绘制像素），但**不阻塞 DOM 构建**（除非 CSS 之后存在 JS 语句，因为 JS 可能查询样式，此时浏览器会强制暂停 JS 直至 CSSOM 就绪）。

- **JavaScript 的解析器阻塞（Parser Blocking）**：
  - **默认脚本**：遇到 `<script>` 无额外标记时，**立即暂停 DOM 构建**，优先下载并执行 JS，防止其通过 `document.write` 篡改 DOM。
  - **异步/延迟加载（优化策略）**：
    - **`async`**：下载不阻塞主线程，下载完成后**立即执行**（执行时阻塞解析）。
    - **`defer`**：下载不阻塞，**等待 DOM 完全构建后**，按顺序执行。

- **关键渲染路径（CRP）与合成**：
  当 **DOM + CSSOM** 就绪后，合并为**渲染树（Render Tree）**（剔除 `display: none` 节点）。随后进入：
  1. **布局（Layout）**：计算可见节点的精确几何位置（盒模型尺寸与坐标）。
  2. **绘制（Paint）**：将元素绘制为独立的位图图层。
  3. **合成（Composite）**：由 GPU 将多个图层按顺序合成，最终显示在屏幕上。

---

### 5. 页面“就绪信号”与生命周期的里程碑（Web API 事件）

浏览器依据 W3C 规范，在关键节点向全局对象派发事件，标记加载状态：

- **`DOMContentLoaded`（内容就绪）**：
  当 **DOM 树构建完毕**，且所有 `defer` 标记的脚本执行完毕后触发。此时外部图片、样式表可能仍在加载中，但页面已具备**可交互的 DOM 结构**。

- **`load`（完全加载）**：
  当页面**所有依赖资源**（包括图片、样式表、异步脚本、iframe 等）均加载并解析完成后触发。此时浏览器标签页的**加载转圈图标**停止转动。

- **`beforeunload` / `unload`（卸载阶段）**：
  用户离开页面时触发，用于执行资源清理或触发“确认离开”弹窗。

### 附：性能核心指标映射（Web Vitals）

> [!WARNING] 工程实践关联
> 上述流程各阶段直接决定了以下用户体验关键指标：

- **FP（首次绘制） / FCP（首次内容绘制）**：对应第 4 步渲染管线的首次输出，取决于 CSSOM 与 DOM 的聚合速度。
- **LCP（最大内容绘制）**：常落在第 4 步至第 5 步之间，受制于图片/文本块的加载与布局完成时间。
- **TTI（可交互时间）**：严格受限于第 4 步中 JavaScript 的长任务（Long Tasks）占用主线程的时间。
- **TBT（总阻塞时间）**：衡量主线程被 JS 执行、解析、布局任务锁定的总时长。
